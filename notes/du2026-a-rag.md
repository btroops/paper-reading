# A-RAG: Scaling Agentic Retrieval-Augmented Generation via Hierarchical Retrieval Interfaces

## Why

检索增强生成（retrieval-augmented generation, RAG）要解决的问题是：模型参数里没有的知识，去外部语料里取回来再回答。取回来的方式决定了系统的上限。过去几年有两条主流路线，它们都把"取什么"在提问之前就定死了。

第一条是单次检索。系统把问题编码成向量，从索引里取回固定的 top-$k$ 段（通常是 5 段），拼进提示词，再让模型回答。图结构路线在这条线上加了结构：GraphRAG 先抽实体和关系建图，RAPTOR 递归摘要建树，HippoRAG 用个性化 PageRank 模仿海马体索引（Edge et al., 2025; Sarthi et al., 2024; Gutiérrez et al., 2025a）。结构让一次检索能覆盖更多相关信息，但取哪几段仍由预设算法决定。问题在于多跳问题：答案需要 A 段的实体去查 B 段，而 B 段在第一次检索时根本不相关。初始 top-$k$ 没覆盖到，后面再强的推理也补不回来，因为被过滤掉的文档已经不在上下文里了。

第二条是预定义工作流。FLARE 在生成置信度下降时触发检索，IRCoT 把思维链和检索交替起来，Self-RAG 让模型判断要不要检索，RA-ISF 用迭代自反馈拆问题（Jiang et al., 2023; Trivedi et al., 2023; Asai et al., 2023; Liu et al., 2024）。这些方法确实多轮了，但轮次、触发条件、每轮取多少，都是设计时写死的。模型可以决定"这一轮查什么"，不能决定"要不要换一种查法""什么时候已经够了"。训练式方法（如 Search-R1）把策略学进权重，换模型或换语料就要重训，也不适合"模型能力每半年翻一代"的节奏。

这两条路线的共同机制缺陷是：模型被排除在检索决策之外。它拿到的是别人替它选好的段落，或者别人替它写好的流程。模型自己的推理能力——分解子问题、发现线索冲突、判断证据是否充分——在检索环节用不上。而前沿模型恰恰在长程工具使用上进步最快：它们能连续调用几十次工具、根据观察改计划、在信息足够时主动停。RAG 系统却没有把这个能力接进来。

这里有一笔很容易被忽略的成本账。固定 top-$k$ 的成本不在检索，而在上下文：每段约 1,000 token，$k=5$ 就是 5,000 token 起，不管问题难易都付这个钱。图结构路线还要额外付建图成本：抽实体、抽关系、跑社区检测，语料一变就要重建。如果让模型自己按需取，简单问题只读一块，难问题多读几块，理论上能在更少 token 下拿到更准的证据。但"按需"意味着接口要足够细，细到模型能表达"我要找含这个短语的块""我要看语义相近的句子""我要读这一整块"。接口太粗，模型只能整块整块地拿，token 反而更费。

于是问题可以写成四问。第一，把检索接口直接暴露给模型，让它自己选粒度、自己决定何时停，能不能在相同或更少 token 下超过图结构路线和工作流路线？第二，如果只给一个最普通的向量检索工具，让模型多轮调用，收益有多大——也就是说，收益里有多少来自"自主"，多少来自"工具分层"？第三，这套系统的表现会不会随模型变强和测试时算力变多而继续涨？第四，当模型自己掌舵后，失败会从"找不到文档"转移到哪里？

## What

先交代任务。输入是一个文档语料、一个自然语言问题，以及三个可调用的检索工具；输出是一段最终答案。系统不训练模型，不改模型权重，也不要求语料带图结构或人工标注；它只决定模型能看到哪些工具、工具返回什么粒度的信息。边界是：它不研究新的索引结构（索引只有分块和句向量），不研究新的训练目标，也不处理需要多模态证据的任务。

论文的答案是：把检索做成三层接口，交给模型在循环里自己用，效果和 token 效率都更好。这三个工具是关键词检索（`keyword_search`）、语义检索（`semantic_search`）和整块阅读（`chunk_read`）。关键词检索做字面匹配，返回含关键词的句子片段；语义检索用句向量找语义相近的句子，再按父块聚合；整块阅读按块编号返回完整正文。模型像用终端工具一样，每轮选一个调用，看结果，再决定下一步；当它认为证据够了，就直接给答案。

在这个设定下，GPT-5-mini 作为 backbone 时，A-RAG（完整版）在五个评测子集上都排第一：MuSiQue 的 LLM 判定准确率（LLM-Acc）74.1、HotpotQA 94.5、2WikiMultiHopQA 89.7、GraphRAG-Bench 的医学子集 93.1、小说子集 85.3（Table 1）。同一张表里，最强的图结构基线 HippoRAG2 分别是 61.7、84.8、82.0、78.2、54.3；线性 RAG 基线 LinearRAG 是 62.4、86.2、87.2、79.2、54.7。换成 GPT-4o-mini 后，A-RAG 在 MuSiQue、HotpotQA 和 GraphRAG-Bench 两个子集上第一，在 2Wiki 上低于 HippoRAG2 与 LinearRAG。论文表述为"5 个数据集里 3 个最好"，按 benchmark 数是 3 个（MuSiQue、HotpotQA、GraphRAG-Bench），按子集数是 4 个；2Wiki 是明确的败场。`[已验证，Table 1]`

### 新认识：自主性本身就能换来准确率，分层接口再换来 token 效率

第一个认识是，"让模型自己多轮检索"这件事的收益，比论文标题暗示的更大。作者做了一个简化版 A-RAG（Naive）：只给一个最普通的向量检索工具，加上整块阅读，不给关键词检索，也不给句子级片段。这个版本在 GPT-5-mini 上已经全面超过 GraphRAG、MA-RAG、RAGentA 和 FaithfulRAG：MuSiQue 66.2 对 GraphRAG 48.3、HotpotQA 90.8 对 82.5、2Wiki 70.6 对 66.5（Table 1）。它甚至接近或超过 HippoRAG2 与 LinearRAG 的部分格。也就是说，不需要图结构，不需要训练，只要把"取哪几段"的决定权交给模型，就能拿到一部分收益。`[已验证，Table 1；但 Naive 版与 Naive RAG 的提示词不同，见 Ideas]`

第二个认识是，分层接口的主要贡献不是"更准"，而是"用更少 token 拿到同等或更准的证据"。Table 3 里，A-RAG（Naive）在 GPT-5-mini 上每题检索 56,360 / 27,455 / 45,406 / 23,657 / 22,391 token（MuSiQue / HotpotQA / 2Wiki / Med / Novel），而完整版只要 5,663 / 2,737 / 2,930 / 7,678 / 6,087。在 MuSiQue、HotpotQA、2Wiki 上，完整版的检索 token 约为 Naive 的十分之一；在 Med、Novel 上约为三分之一，仍更少。准确率反而更高。原因在返回粒度：Naive 版每次只能整块读，一块约 1,000 token；完整版先返回含关键词的短句，模型判断有用再读整块，没用的块根本不进上下文。这个对比把"渐进披露"（progressive disclosure）的作用量化了。`[已验证，Table 3；口径只算工具返回的 token，不含模型输入输出，见 How 六]`

第三个认识是，范式换了以后，失败的位置也换了。作者人工检查了 MuSiQue 上 100 个错误案例：朴素 RAG（GPT-4o-mini）约一半错误来自检索（多跳检索失败 36%、top-$k$ 不足 15%），而 A-RAG（GPT-5-mini）82% 的错误是推理链错误——文档已经找到，但模型在实体消歧或线索组合上出错。二级分类里实体混淆占 40%（MuSiQue）和 71%（2Wiki）。这说明继续优化检索器对 A-RAG 的边际收益在下降，瓶颈转到了"读对了但想错了"。`[已验证，Table 6–8；样本是前 100 个错误，不是随机抽样]`

### 新方法：三个工具、一个循环、一个已读集合

可复用的第一件东西是接口分层。它没有发明新的索引，只是把同一份语料用三种粒度暴露出来：关键词级是运行时字面匹配，不建倒排索引；句子级是预计算的稠密向量；块级是原文。三种粒度对应三种问法——"这个实体名出现在哪""这段意思相近的话在哪""这一整块到底说了什么"。模型可以先用关键词锁定实体，再用语义检索找同义表述，最后读整块确认上下文。

第二件是渐进披露的返回格式。两个检索工具都不直接返回整块正文，而是返回"块编号 + 命中句子片段"。片段用省略号标出截断位置，提示模型这只是线索，要读全文必须再调 `chunk_read`。这个设计把"定位"和"阅读"拆成两次调用，模型只在确认相关后才付整块的 token。

第三件是已读集合。系统记录模型读过的块编号；同一块再次被请求时，工具只回一句"This chunk has been read before"，不返回正文，消耗零 token。这既防重复读取，也逼模型去探索语料的其他部分。它不记录检索过的块，只记录读过的块，所以重复检索仍会花 token，见 Ideas。

### 新结论：规模、算力与失效边界

测试时扩展（test-time scaling）有两个方向，论文都给了曲线。固定模型、把最大迭代步数从 5 提到 20，GPT-5-mini 的 LLM-Acc 提升约 8 个百分点，GPT-4o-mini 只提升约 4 个百分点；步数越多，强模型的优势越大，说明长程探索能力本身是收益来源。固定步数、把推理强度（reasoning effort）从 minimal 提到 high，GPT-5-mini 与 GPT-5 都提升约 25 个百分点（Fig. 4）。这两个数都来自 MuSiQue 的前 300 题，没有置信区间。`[已验证，§5.1；样本是子集，且 §5.1 用了 GPT-5，与 Limitations 冲突]`

失效边界有三类。第一类是任务边界：四个数据集都是多跳问答，作者明确说事实核验、对话系统、长文生成没验证（Limitations）。第二类是模型边界：GPT-4o-mini 上 A-RAG 并非全面领先，2Wiki 输给两个图结构基线；模型越弱，自主多轮检索越容易走偏。第三类是评估边界：LLM 判定器本身会错，A-RAG 的错误里有 9%（MuSiQue）和 19%（2Wiki）是"答案对但被判错"，朴素 RAG 那边是 14% 和 23%（Table 6–7）。这意味着主表上几个点的差距有一部分是判定噪声。

## How

这篇论文跨两类。系统与算法类：它给出索引结构、三个工具的接口定义、一个 ReAct 式循环和已读集合的实现。实证与基准类：它在四个多跳问答数据集、两个 backbone、八个基线上做端到端比较，另有消融、token 统计、扩展曲线和失败分析。判型依据是它既给出可复用的机制，又用统一复现的实验验证；没有定理，没有新的训练目标，也不训练模型。下面按"索引—工具—循环—实验—结果—成本—失败"展开。

### 一、索引只有两步：切块与句子向量

语料被切成约 1,000 token 的块，切点对齐句子边界，保证每块语义完整（§3.1）。每块再按规则切成句子 $\{s_{i,1},\dots,s_{i,n_i}\}$，用预训练的句子编码器 $f_{\text{emb}}$ 给每句算一个稠密向量 $v_{i,j}=f_{\text{emb}}(s_{i,j})$。句子向量保留到父块的映射，所以语义检索命中句子后能回到整块。

关键词级不建索引。作者的理由是省掉离线建倒排索引或知识图谱的时间与算力；查询时直接对原文做大小写不敏感的精确匹配。这个选择的代价是每次关键词检索都要扫全语料，语料大时延迟会线性涨；论文没有报检索延迟，也没有报语料规模，见 Ideas。

三层信息因此是这样组织的：关键词级是隐式的（运行时匹配），句子级是显式的（预计算向量），块级是原文（按编号取）。这也解释了为什么索引成本低：只有切块和一次句子编码，没有实体抽取、关系抽取、社区检测。

### 二、三个工具：每个都只返回线索，不返回全部

**关键词检索**接收一个关键词列表 $K=\{k_1,\dots,k_m\}$ 和一个返回条数 $k$。块 $c_i$ 的得分是

$$
\operatorname{Score}_{\text{kw}}(c_i,K)=\sum_{k\in K}\operatorname{count}(k,T_i)\cdot|k|,
$$

其中 $\operatorname{count}(k,T_i)$ 是关键词 $k$ 在块文本 $T_i$ 里出现的次数，$|k|$ 是关键词的字符长度。乘字符长度是作者的启发式：越长的关键词通常越具体，命中它应该比命中一个短停用词更有信息量。这个打分没有逆文档频率（inverse document frequency, IDF），也没有文档长度归一化，所以长块和含重复词的块天然占优；它不等于 BM25，见 Ideas。

每个命中的块返回一个缩写片段：只保留包含至少一个关键词的句子，

$$
\operatorname{Snippet}(c_i,K)=\{s\in\operatorname{Sent}(c_i)\mid \exists k\in K,\ k\subseteq s\},
$$

其中 $\operatorname{Sent}(c_i)$ 是块 $c_i$ 的句子集合，$k\subseteq s$ 表示关键词作为子串出现在句子 $s$ 里。工具返回 top-$k$ 块编号加片段，不返回全文。

**语义检索**接收自然语言查询 $q$，编码成 $v_q=f_{\text{emb}}(q)$，与所有句子向量算余弦相似度：

$$
\operatorname{Score}_{\text{sem}}(s_{i,j},q)=\frac{v_{i,j}^{\top}v_q}{\lVert v_{i,j}\rVert\,\lVert v_q\rVert}.
$$

取出得分最高的若干句子，按父块聚合；一个块的分数取它内部最高分句子的分数。返回 top-$k$ 块编号加命中句子。这样做的效果是：块里有任何一句与查询相近，整块就会被召回，但模型只看到那一句，不会被整块的无关内容干扰。

**整块阅读**接收块编号列表，返回这些块的完整正文。模型可以读相邻块（$\pm1$）补上下文。已读集合 $C_{\text{read}}$ 记录读过的块；再次请求同一个块时，工具返回固定提示，不返回正文，token 消耗为零。注意 $C_{\text{read}}$ 只在 `chunk_read` 时更新，检索不更新。

### 三、循环：每轮一个工具，够了就答

循环是 ReAct 式的（Yao et al., 2023）：维护消息历史 $M_{\text{msg}}$，初始只有问题；每轮把历史和工具列表给模型，模型要么返回一个工具调用 $(t,\text{args})$，要么返回最终答案。如果是工具调用，执行结果追加到历史，进入下一轮；如果到了最大迭代步数 $L$ 还没有答案，就追加一句"Answer the question"，让模型用已有信息合成回答（Algorithm 1）。

作者刻意不加并行工具调用，也不加复杂的编排器。理由是要把"接口设计"的影响单独观察出来：如果同时加了规划器、并行调用、反思模块，收益就分不清来自哪里。这个选择也让实验更干净，但代价是延迟：每个工具调用都要等一次模型生成，串行 $L$ 轮就是 $L$ 次生成加 $L$ 次检索。

提示词很短。完整版的系统提示只说明三个工具、建议"search → read → evaluate → search → ... → answer"的循环，并对多跳问题加了一句"分解问题，逐步解决每个子问题"。朴素版只说明一个向量检索工具和整块阅读，策略描述是"retrieve → read → answer"（Fig. 6）。两版的差别不只是工具，还有这句多跳分解指令，见 Ideas 第二条。

### 四、实验设置：统一复现，但有几处口径要记住

数据集是 HotpotQA、2WikiMultiHopQA、MuSiQue 和 GraphRAG-Bench，后者的医学（Med.）与小说（Novel）两个子集分别报告；语料与题目沿用 LinearRAG 的设置（§4.1）。基线分两组：朴素组是直接回答与朴素 RAG；结构与工作流组是 GraphRAG、HippoRAG2、LinearRAG、FaithfulRAG、MA-RAG、RAGentA。所有方法统一用 top-$k=5$、`max_tokens≥16,384`，稠密检索统一用 Qwen3-Embedding-0.6B，LinearRAG 因命名实体识别模块不兼容而用它自己的编码器（§4.1, Appendix B）。

指标有两个。LLM-Acc 用 GPT-5-mini 当判定器，判断预测与标准答案是否语义等价；Contain-Acc 判断标准答案是否作为子串出现在生成文本里。短答案数据集（HotpotQA、2Wiki、MuSiQue）两个都报；GraphRAG-Bench 是长描述答案，只报 LLM-Acc，因为标准答案很少逐字出现（§4.1）。判定器用 GPT-5-mini 的理由是作者人工核验后认为它更准更稳；但它同时也是被评测的两个 backbone 之一，见 Ideas。

### 五、结果：完整版赢在准确率，简化版赢在"证明自主性有用"

Table 1 的关键格前面已经给过，这里补三组对照。第一，A-RAG（Naive）对朴素 RAG：GPT-5-mini 上 MuSiQue 66.2 对 52.8、HotpotQA 90.8 对 81.2、2Wiki 70.6 对 50.2、Med 92.7 对 86.1、Novel 80.4 对 70.6，全部更高。第二，A-RAG（Full）对 A-RAG（Naive）：74.1 对 66.2、94.5 对 90.8、89.7 对 70.6、93.1 对 92.7、85.3 对 80.4，全部更高，2Wiki 的 +19.1 最大。第三，GPT-4o-mini 上 Full 对 Naive 的增益小得多（46.1 对 43.8、77.1 对 76.6、60.2 对 52.3、79.4 对 79.0、72.7 对 70.0），说明分层接口要配强模型才兑现。

消融只做了 GPT-5-mini，三个变体各去掉一个工具（Table 2）。去掉语义检索掉得最多：MuSiQue 74.1→69.4（-4.7），2Wiki 89.7→89.1（-0.6），Med 93.1→92.1（-1.0）。去掉关键词检索影响较小：MuSiQue 74.1→72.6（-1.5），2Wiki 89.7→88.9（-0.8），Med 反而 93.1→93.2（+0.1）。去掉整块阅读时，作者同时把两个检索工具的返回从片段改成全文，所以这个变体不是"少一个工具"，而是"换一种信息呈现"：MuSiQue 73.6（-0.5）、HotpotQA 93.6（-0.9）、2Wiki 89.0（-0.7），但 MuSiQue 的 Contain-Acc 67.0 反而高于完整版的 65.3，HotpotQA 的 Contain-Acc 88.8 也高于 88.0。论文说完整配置整体最优，严格按格看并不是每格都最优，见 Ideas。

### 六、成本：只报了检索 token，没报总账

Table 3 的列名是"retrieved tokens"，统计的是工具返回给模型的文本量，不含系统提示、模型生成的推理、工具调用的 JSON。按这个口径，完整版在五个子集上分别是 5,663 / 2,737 / 2,930 / 7,678 / 6,087，与朴素 RAG 的 5,387 / 5,358 / 5,506 / 5,418 / 4,997 同量级或更低；简化版是 56,360 / 27,455 / 45,406 / 23,657 / 22,391，高一个数量级。GraphRAG 在 MuSiQue 上 9,234、Med 9,391、Novel 9,318，比完整版高。

这个口径会低估 agentic 系统的真实成本。完整版每道题要跑多轮模型生成，每轮都要把历史重新编码；简化版虽然检索 token 高，但如果它只跑两三步，总成本未必更高。论文没有报每题的模型调用次数、输入输出 token 总量、端到端延迟或 API 费用。建索引的成本也没有报：切块与句子编码需要多少时间、多少算力、语料规模多大，都不在表里。所以"token 效率更高"这个结论只在检索 token 这个口径上成立，不能直接推成"总成本更低"。

### 七、失败分析：瓶颈从检索转到推理

作者人工看了 100 个错误案例，分两级归类。朴素 RAG（GPT-4o-mini）的错误里，模型理解 36%/35%、多跳检索 27%/36%、判定错误 23%/14%、top-$k$ 不足 13%/15%（HotpotQA/MuSiQue，Table 6）。A-RAG（GPT-5-mini）的错误里，推理链错误 82%/45%、模型放弃 3%/33%、判定错误 9%/19%、语料缺失 6%/3%（MuSiQue/2Wiki，Table 7）。推理链错误内部，实体混淆 40%/71%、策略错误 28%/29%、问题理解错误 22%/0%、超出预算 10%/0%（Table 8）。

这组数字说明两件事。第一，"找到文档"不再是主要瓶颈：语料缺失只占 3–6%，而朴素 RAG 那边多跳检索加 top-$k$ 不足占 50% 左右。第二，剩余错误集中在实体消歧：模型读到了含标准答案的块，但被块里其他同名实体或相似数字带偏。这为下一步优化指了方向——不是换更强的检索器，而是给模型实体级的选择或验证工具。

## Ideas

### 不足

**评估与统计**

1. 主表所有数字都是单次运行，没有置信区间，也没有重复实验的方差。几个点的差距（例如 GPT-4o-mini 上 Full 对 Naive 的 +0.4）很可能落在运行噪声里。`[评估问题]`
2. LLM-Acc 的判定器是 GPT-5-mini，而 GPT-5-mini 同时是被评测的两个 backbone 之一。同家族模型当裁判可能高估自己家族的输出；论文只写"人工核验后认为更准更稳"，没有给判定器与人工的一致率。失败分析里判错占 9–19%，本身已经说明指标有噪声。`[评估问题]`
3. 失败分析看的是"前 100 个错误"，不是随机抽样。数据顺序可能让某类错误集中出现；作者没有给抽样方法，也没有给第二标注者的一致性。`[评估问题]`
4. GraphRAG-Bench 的医学子集区分度很低：GPT-5-mini 直接回答就有 90.5，朴素 RAG 反而降到 86.1，A-RAG 93.1 只比直接回答高 2.6。这个子集上"检索有没有用"本身存疑，用它证明 A-RAG 的优势不牢。`[评估问题]`

**方法与归因**

5. Full 与 Naive 的差别不止工具集：完整版的系统提示多了一句"对多跳问题分解并逐步解决"，朴素版没有。因此 Full 的增益里有一部分来自提示策略，不是接口分层。`[方法问题]`
6. "w/o Chunk Read"这个消融同时改了两件事：去掉阅读工具，并把检索返回从片段换成全文。它测的是"片段+按需阅读"对"直接给全文"，不是"有没有 chunk_read"。`[方法问题]`
7. 关键词检索的打分是词频乘字符长度，没有 IDF、没有长度归一化、没有 BM25 的饱和项。它和标准稀疏检索的差距没有被测；论文也没有把 BM25 作为基线或工具变体。`[方法问题]`
8. 已读集合只记录 `chunk_read`，不记录检索命中。同一批块可以被反复检索、反复返回片段，token 照付；这个明显的冗余没有被处理。`[方法问题]`
9. 每轮只允许一个工具调用，是刻意简化，但也意味着 20 步上限就是 20 次工具调用；扩展曲线里的收益有多少来自"多步"，有多少来自"每步更强的模型"，没有拆开。`[方法问题]`

**系统与成本**

10. 关键词检索在查询时扫全语料，复杂度随语料线性涨；论文没有报语料规模、块数、检索延迟，也没有报 p50/p99。`[系统问题]`
11. 只报检索 token，不报模型输入输出 token、调用次数、端到端延迟、API 费用；建索引的时间与算力也没有。因此不能判断 agentic 方案在真实部署里是否比固定 top-$k$ 便宜。`[系统问题]`
12. 没有给最大迭代步数的默认值、块大小之外的超参、判定器提示词、随机种子。可复现性依赖代码仓库，但论文本身不足以复现。`[系统问题]`

**内部矛盾**

13. §5.1 写"GPT-5-mini 与 GPT-5 都提升约 25%"，Fig. 4 右图也标了 GPT-5；但 Limitations 明确说"由于算力限制，没有在 GPT-5 上验证"。两处冲突，主文引用 GPT-5 的数字时需要注明。`[评估问题]`
14. 正文说 GPT-4o-mini 上 A-RAG 在"5 个数据集里 3 个最好"，按 LLM-Acc 逐子集数其实是 4 个（MuSiQue、HotpotQA、Med、Novel），只有 2Wiki 不是；按 benchmark 数才是 3 个。这个表述取决于把 Med/Novel 算一个还是两个数据集。`[评估问题]`

### 创新点

**一、把关键词工具换成 BM25，做单变量替换实验**

- **主张**：如果 A-RAG 的关键词工具改用 BM25 的 IDF 加权与长度归一化，那么在实体名密集的多跳数据集上，相同步数预算下的准确率会上升，检索 token 不增。
- **与原文关系**：增量。原文的 $\text{count}\times|k|$ 是一个没有文档频率校正的启发式，BM25 是它的标准替代。
- **最小验证**：固定同一套提示词、同一个 backbone、同一个 20 步预算，只替换 `keyword_search` 的打分函数；在 MuSiQue 与 2Wiki 上比较 LLM-Acc、Contain-Acc 和检索 token。预期 MuSiQue 提升 1–3 点，2Wiki 提升更小。同时加一个只用 BM25 的单工具版本，检验"稀疏检索单独是否够"。
- **失败条件**：BM25 不提升，或提升小于 1 点，或检索 token 明显增加。这说明瓶颈不在词面匹配质量，而在模型如何使用返回结果。

**二、对齐 Full 与 Naive 的提示词，拆开"自主性"与"接口分层"**

- **主张**：把两个版本的系统提示改成只差工具描述（去掉完整版额外的多跳分解指令），Full 相对 Naive 的增益会缩小；缩小后的差值才是分层接口的真实贡献。
- **与原文关系**：反驳/修正。原文把 Full 的优势归因于层次化接口，但提示词不是单变量。
- **最小验证**：四个配置的 2×2：工具集（单工具/三工具）× 提示（基础/多跳分解），在 MuSiQue 与 2Wiki 上各跑一遍，报 LLM-Acc 与检索 token。预期多跳分解指令单独也能带来一部分增益，接口分层的净增益小于原文的 +19.1（2Wiki）。
- **失败条件**：四个配置的差值显示提示词贡献小于 1 点，接口分层的净增益仍接近原文。这反而加强原文结论。

**三、给 agent 一个显式检索预算，让它自己分配**

- **主张**：把"最多读多少 token"作为可观察的状态交给模型，让它自己决定每次检索和阅读花多少，能在相同总 token 下比固定 top-$k$ 更准，尤其在难易混合的测试集上。
- **与原文关系**：扩展。原文只限制步数，不限制 token；步数与 token 不成正比（读整块和读片段差一个数量级）。
- **最小验证**：在提示里加入剩余预算，工具返回时扣减；对 MuSiQue 按难度分层（1–4 跳），比较固定预算与自适应预算的准确率- token 曲线。预期自适应预算在简单题上省 token、在难题上多花 token，整体曲线更靠左上。
- **失败条件**：自适应预算的曲线被固定预算支配，或模型不会根据预算改变行为（预算提示被忽略）。

**四、把实体消歧做成一个工具，直接针对最大失败模式**

- **主张**：既然 40–71% 的推理链错误是实体混淆，给 agent 一个"列出一个块里所有同名实体及其属性"的工具，能显著降低这类错误。
- **与原文关系**：扩展，直接接原文的失败分析。
- **最小验证**：在 MuSiQue 的 100 个错误案例上做干预实验：同一问题、同一模型，加一个实体列表工具，比较修复率与新增 token。预期修复 15–30% 的实体混淆案例。
- **失败条件**：修复率低于 10%，或新增工具让模型在无关块上浪费步数、总体准确率下降。

**五、把检索日志变成可训练的信号**

- **主张**：A-RAG 的完整轨迹（每轮查什么、读什么、最后答什么）可以作为过程监督数据，训练一个小模型学会"什么时候该换工具、什么时候该停"，从而在不损失准确率的情况下减少步数。
- **与原文关系**：正交。原文不训练，只评测现成模型；这条线把轨迹当数据。
- **最小验证**：用 GPT-5-mini 在 MuSiQue 训练集上跑 A-RAG，收集成功轨迹；蒸馏一个 7B 模型预测下一步工具与参数；在测试集上比较步数、准确率与 token。预期步数下降 30%，准确率掉不超过 2 点。
- **失败条件**：蒸馏后准确率掉超过 5 点，或步数不降。这说明轨迹里的决策依赖强模型的隐式判断，不易蒸馏。

**六、跨论文：把 SAGE 的语料级增强接到关键词工具上**

- **主张**：SAGE 发现给文档补充元数据与关键词能让现成检索器更好用；把同样的增强写进 A-RAG 的索引，让 `keyword_search` 能命中人工补充的别名与领域词，能提升低资源领域（如医学子集）的召回。
- **与原文关系**：正交，组合两篇论文的机制。
- **最小验证**：在 GraphRAG-Bench 医学子集上，对每个块生成 5–10 个别名/关键词并存入索引，比较增强前后的 LLM-Acc 与检索命中率。预期医学子集提升 2–5 点。
- **失败条件**：增强后没有提升，或生成的别名引入噪声、准确率下降。这说明该子集的瓶颈不是词面不匹配。

## 相关工作

仓库内与本文最接近的是 [wan2026-decision-rag](wan2026-decision-rag.md)：两者都把层级检索的"展开哪一支"交给一个判断器，但 DecisionRAG 的控制器是一个专门的决策模型，逐层选分支；A-RAG 的控制器就是被测的 LLM 本身，通过工具调用选粒度。前者把控制策略从生成模型里拆出来，后者把控制权交回生成模型，方向相反。

[kumar2026-stair](kumar2026-stair.md) 也把结构当检索单位，但它的结构是书的目录，输出是叶标题；A-RAG 的结构是块与句子的两级粒度，输出是证据片段。两者可以组合：先用目录定位章节，再用 A-RAG 的工具在章节内细查。

[bao2026-raw-rag](bao2026-raw-rag.md) 的结论是"配好的原始历史检索比复杂记忆系统更强"，本文的 A-RAG（Naive）给出了同一方向的另一个证据：最简单的向量工具加自主多轮，已经超过一堆复杂基线。两篇都在提醒：先确认基线够强，再谈结构。

[he2026-memory-tax](he2026-memory-tax.md) 提供了收益/税账本的口径；本文只报了检索 token，没有报总成本，正好是那套账本要补的维度。

[ho2026-declarative-attention](ho2026-declarative-attention.md) 让模型自己声明"这一步读哪些 KV 块"，本文让模型自己声明"这一步查哪个粒度的检索接口"。两者都是把控制信号从外部评分器搬到模型输出里，区别是一个作用于注意力掩码，一个作用于工具调用。

## 可复现

- 代码与评测套件：<https://github.com/Ayanami0730/arag>（Abstract 声称会放出）。
- 数据：HotpotQA、2WikiMultiHopQA、MuSiQue、GraphRAG-Bench 均为公开数据集；语料与题目沿用 LinearRAG 的设置，需同时取 LinearRAG 的预处理版本。
- 模型：GPT-4o-mini、GPT-5-mini 通过 API 调用；稠密检索用 Qwen3-Embedding-0.6B；LinearRAG 用它自己的 `all-mpnet-base-v2`。
- 关键超参：块约 1,000 token、句子边界对齐；top-$k=5$（工具默认 5，最大 20）；`max_tokens≥16,384`；最大迭代步数 $L$ 的具体值论文未给，只给了扩展实验里的 5 与 20。
- 无法复现的部分：语料规模与块数、每数据集题数、最大步数默认值、判定器提示词、随机种子、API 版本与温度、检索延迟、总 token 与费用。论文没有给这些，需从代码仓库补。
