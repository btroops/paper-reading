# SAGE: Benchmarking and Improving Retrieval for Deep Research Agents

## Why

深度研究 agent（deep research agent）的工作方式是：拿到一个复杂问题，先想，再拆成若干子查询，调用搜索工具，读结果，再想，再查，最后综合成带引用的答案。它的能力上限很大程度上由检索栈决定：如果检索器返回的文档不对，后面的推理再强也只能在错误证据上打转。

要理解过去两年检索侧的进步，先要区分两种检索方式。第一种是词面匹配，代表是 BM25：它把文档看成一袋词，离线建倒排表，查询时对每个词按出现次数和稀有度加权求和。它只认字面，但年份、会议名、模型名这些精确约束会被完整保留。第二种是稠密检索：训练一个编码器，把整段文本压成一个固定长度的向量，查询和文档各算一个向量，检索时取余弦相似度最高的前 $k$ 篇。它认语义，同义改写也能匹配，但整段文本被压成一个向量后，细粒度的词面约束会被稀释。两种方式的完整机制、公式和训练过程见 [稠密检索：文本怎么变成向量](concepts/dense-retrieval.md)。

"让检索器也会推理"是稠密检索的近期版本，常见做法有三类：把 BERT 换成 7B 级的大模型，用它的隐藏状态做向量（LLM2Vec、GritLM、gte-Qwen2-7B-instruct）；用指令微调让模型知道当前是哪种检索任务（Promptriever、gte-Qwen2-instruct）；用推理链把短查询扩写成带步骤的长文本再编码（HyDE、Query2Doc）。SAGE 对比的 ReasonIR 不属于这三类，它是用推理密集型数据训练的稠密检索器。

这套做法在 BEIR、MTEB 这类基准上确实比 BM25 强。原因有两个。第一，这些基准的查询是完整的自然语言问句，文档是段落，评分看的是"意思是否相关"，不是"词是否出现"；同义改写、换个说法问同一件事，稠密向量能匹配上，BM25 匹配不上。第二，这些基准的查询写法与稠密检索器训练时见到的写法一致：训练数据主要是问句-文档对，测试时还是问句，模型不需要适应新的输入形式。

第二个原因同时是一个条件：稠密检索的优势依赖"查询的写法与训练时一致"。如果查询从完整问句变成几个关键词的拼接，输入写法变了，模型在训练时学到的匹配方式不一定还成立。所以"在标准基准上更强"不能直接推成"在 agent 场景也更强"；中间还差一步：agent 生成的查询到底长什么样。

这个条件在 agent 场景里未必成立。agent 生成的子查询，和这些检索器训练时见到的查询，往往不是同一种东西：真实 agent 的子查询不是完整的自然语言问句，而是几个关键词的拼接，比如 "ICML 2023 symbolic regression ODEFormer Feynman physics-informed"。这种查询对 BM25 是友好的：词面匹配、词频加权、倒排索引，正好处理关键词堆叠。对稠密检索器反而不友好：它的训练分布是自然语言问句，编码器会把关键词串压成一个语义向量，细粒度的词面约束（年份、会议名、数字）在向量里被稀释。如果这个错配成立，那么"更强的检索器"在 agent 工作流里可能反而更弱。

要验证这件事，需要一个可控的测试台。现有的深度研究基准大多依赖开放网络和商业搜索 API：语料每天都在变，检索后端是黑盒，无法判断一个 agent 的失败是"查询没写好"还是"检索器没返回"。开放网络还允许模型用参数知识直接答题，掩盖检索的作用。科学文献检索适合做这个测试台：语料是固定的论文集合，问题需要跨论文的元数据、图表细节和引用关系推理，答案唯一且可验证；论文本身又是长文档，能暴露稠密检索在长输入上的截断问题。

成本账也在推动这件事。为 20 万篇论文建稠密索引，要下载 PDF、转 Markdown、切块、编码，每篇平均 13,376 token，编码成本随语料线性涨；语料一更新，索引就要重建。BM25 只需要倒排索引，构建和更新都便宜得多。如果 BM25 在 agent 工作流里不差，甚至更好，那么"默认上稠密检索"就是一个没有算过账的选择。

于是问题可以写成四问。第一，把同一批深度研究 agent 放到固定语料上，让它们用 BM25、通用稠密检索器、推理型稠密检索器分别做搜索，哪一种检索器在端到端任务上更好？第二，如果 BM25 更好，原因是查询形式、文档长度、还是 agent 的行为？第三，能不能在不改 agent 的前提下，通过改造语料让现成检索器（尤其是稠密检索器）更好用？第四，这种改造的收益有多大，代价是什么？

## What

先交代任务。输入是一个复杂查询（短答案题或开放式文献综述题）和一份固定的论文语料；输出是答案，或在开放式题里给出相关论文列表。评测对象是深度研究 agent：它自己决定何时想、何时查、查什么、何时答。SAGE 不改 agent 的规划逻辑，只替换它背后的检索工具；边界是它不训练 agent，不做指令微调，也不研究多模态检索（论文里的图表信息只以文本形式进入问题）。

论文的答案是：在深度研究 agent 的工作流里，BM25 显著优于 LLM-based 检索器，短答案题上高约 30%（相对），原因是 agent 生成的子查询是关键词式的，与稠密检索器的训练分布错配；通过给每篇论文补充元数据和 8 个关键词，可以把 BM25 的短答案准确率再提高 8.18 个绝对点。

具体数字如下。SAGE 包含 1,200 道题：四个领域（计算机科学、自然科学、医疗健康、人文）各 150 道短答案题和 150 道开放式题；每个领域约 5 万篇论文，总计约 20 万篇（人文因开放获取论文少，约 4 万篇；Table 1）。短答案题用 Exact Match（EM）评，开放式题用加权召回（Weighted Recall）评。用 DR Tulu 当 backbone、每轮返回 top-10 时，BM25 的短答案平均 EM 是 81.2，gte-Qwen2-7B-instruct 是 63.0，ReasonIR 是 49.3；BM25 比 gte-Qwen 高 28.9%（相对），比 ReasonIR 高 64.7%（Table 2）。开放式题上差距缩小：gte-Qwen 33.0、BM25 30.7、ReasonIR 26.2，BM25 不再领先。`[已验证，Table 2]`

### 新认识：查询形式与检索器的训练分布错配，是 agent 检索性能的主要瓶颈

第一个认识是，agent 的子查询是关键词式的，不是自然语言问句。作者对比了 GPT-5 与 DR Tulu 的查询分解：GPT-5 倾向生成短语化、语义结构完整的查询；DR Tulu 的子查询更像关键词拼接（Fig. 7, Fig. 8）。DR Tulu 在网页搜索上的平均 EM 只有 42.0，而 GPT-5 是 71.7；但换成固定语料 + BM25 后，DR Tulu 的 EM 升到 81.2。这个反差说明两件事：DR Tulu 的查询形式不适合开放网络搜索，但很适合词面匹配；它的瓶颈在检索接口，不在推理能力。`[已验证，Table 2；跨设置比较需谨慎，见 Ideas]`

第二个认识是，LLM-based 检索器的失败不是"语义理解不够"，而是"语义被用错了地方"。作者给了一个具体案例（Fig. 4）：查询要找一篇用物理信息启发式的符号回归论文，ReasonIR 把 "physics-informed" 当成标题关键词，反复召回标题含这个词的物理信息神经网络论文，越查越偏；BM25 则被子查询里的 "ODEFormer"、"AI Feynman"、"ICML 2022..2024" 这些词面锚点拉住，没有漂移。这个案例的机制解释是：稠密检索器在长文档上只编码前 32,000 token，且关键词串在向量里被平均掉；BM25 对每个词独立打分，稀有词（会议名、模型名）权重高，正好保留细粒度约束。`[宣称，Fig. 4 是单例；机制解释是我的]`

第三个认识是，搜索方法会改变 agent 使用查询中哪一部分信息。作者把短答案题拆成三个成分：元数据（Met.，如年份、会议、作者数）、图表细节（Det.，如某张图显示 98% 准确率）、论文间关系（Rel.，如共享 14 条引用）。逐个去掉一个成分，看准确率掉多少（Table 3）。网页搜索下，DR Tulu 最敏感的是图表细节（去掉掉 21.60%）；语料搜索下，DR Tulu 最敏感的是论文间关系（去掉掉 24.59%）。更值得注意的是，共用同一个检索后端的 agent 敏感模式相似：DR Tulu 与 Gemini-2.5-Pro 都用 Google Search，都最受细节影响。这说明检索后端决定了 agent 能利用哪类查询信息，而不只是"返回得准不准"。`[已验证，Table 3；相对变化，不是绝对点]`

### 新方法：一个基准、一套语料级增强

第一件可复用的东西是基准本身。SAGE 的短答案题由三段组成：论文元数据（出版年份区间、会议、作者数）、图表细节（某张图/表显示的具体结果）、论文间关系（与另一篇论文共享多少条引用、共同引用哪篇）。答案是那篇种子论文，唯一且可用标题匹配验证。开放式题由研究背景和一对论文的共享引用构成，要求列出相关论文；标准答案分三层：种子论文对最相关（权重 2），它们共享的引用相关（权重 1），其余不相关（权重 0）。这个分层让加权召回能区分"找到核心论文"和"找到周边引用"。

第二件是语料级测试时扩展（corpus-level test-time scaling）。名字里的"测试时"不是指查询时多采样，而是指在评测前对语料做一次增强：用 Qwen3-Next-80B-A3B-Instruct 读每篇论文的 Markdown，生成 8 个主题关键词；再抽取出版会议、年份、作者、引用数等元数据；把这些字段拼成一段"关键词袋"，放在每篇文档开头。这样 BM25 的倒排索引能直接匹配到这些词，稠密检索器也能在输入开头看到它们。作者把这叫"把推理派生的信息放进文档，而不是放进查询"。

### 新结论：收益、边界与口径

语料级增强的收益不均匀。BM25 的短答案 EM 从 75.80 升到 83.98（+8.18 绝对点，相对 +10.8%），开放式加权召回从 25.52 升到 27.25（+1.73 点）；gte-Qwen 只从 46.90 升到 47.80（+0.90），开放式 26.03→27.82（+1.79）；ReasonIR 从 38.70 升到 40.40（+1.70），开放式 17.25→19.79（+2.54）（Table 4）。BM25 受益最大，因为它对关键词信号最敏感；稠密检索器受益小，因为增强的关键词被编码进向量后，语义模型并不会把它们当成硬约束。`[已验证，Table 4]`

边界有三条。第一，开放式题的增益很小（1.73–2.54 点），作者归因于 agent 的查询分解多样性低，覆盖不到多篇标准答案；增强语料只能让"已经会查的那一部分"更好查，不能扩展查询的覆盖面。第二，检索器排序依赖文档长度与证据分布：SAGE 的论文平均 13,376 token，证据分散；BrowseComp-Plus 的文档平均 6,733 token，且 86.5% 的题目前 512 token 就含答案。后者有利于只编码前缀的稠密检索器，前者不利于；所以"BM25 还是稠密更好"没有跨数据集的统一答案（§A.4）。第三，行为分析主要在 DR Tulu 上做，作者承认它的后训练配方可能影响结论，换一个 agent 未必复现（Limitations）。`[已验证，§A.4, Limitations]`

## How

这篇论文以实证与基准类为主，附系统与算法类。实证与基准类：它构造了一个 1,200 题、20 万篇论文的基准，定义了两套指标，比较了六种 agent、三种检索器、两种 top-$k$。系统与算法类：它提出并实现了一套语料级增强流程（元数据抽取 + 关键词生成 + 文档前置），以及 DR Tulu 的 MCP 检索接口改造。判型依据是它既给出可复用的数据和评测装置，又用端到端实验验证；没有定理，没有新的训练目标，也不训练检索器或 agent。下面按"数据—指标—语料—实验—结果—增强—成本"展开。

### 一、短答案题：三段式约束，答案是种子论文

短答案题的构造从种子论文开始。作者在每个领域的主要会议（计算机科学是 ACL、ICML、NeurIPS 等）里选一篇 2024 年之后发表的种子论文，再按引用重叠选一篇相关论文：两篇论文的参考文献至少共享 4 条，才算相关。然后抽取三类信息：论文元数据（出版年份、会议、作者数）、用 PyMuPDF 抽的图表与表格细节、以及两篇论文的引用重叠（共享多少条、共同引用哪篇）。最后用 GPT-5-mini 把这些信息写成一道题，答案是种子论文本身（§3.2）。

这个构造有三个后果。第一，问题的每一段都对应一个可验证的约束，模型不能靠"猜主题"答对。第二，问题里包含大量词面线索：会议名、年份、作者数、图表里的数字、共享引用的标题。这些线索对 BM25 友好，对稠密检索器不一定。第三，答案是种子论文，而种子论文及其引用网络被放进了语料；问题与语料同源，见 Ideas。

### 二、开放式题：分层标准答案与加权召回

开放式题从一对种子论文的共享引用出发。作者先用 GPT-5-mini 分析两篇论文的关系、为什么共享这些引用，再生成一段研究背景和查询指令。标准答案分三层：种子论文对权重 2，它们共享的引用权重 1，其余权重 0。指标是加权召回：

$$
\text{Weighted Recall}=\frac{\sum_{d\in L}g(\operatorname{rel}(d))}{\sum_{d\in G}g(\operatorname{rel}(d))},
$$

其中 $L$ 是系统返回的文档集合，$G$ 是所有相关文档，$g(r)=r$ 是线性增益，$\operatorname{rel}(d)\in\{0,1,2\}$ 是文档的相关等级。这个指标的分子只算返回的相关文档，分母是所有相关文档的权重和；它衡量"找回多少权重"，不惩罚返回无关文档。换句话说，多返回总是不会更差，见 Ideas。

### 三、语料：每域 5 万篇，但两个题型的可用库不同

每个领域的目标语料是 5 万篇开放获取论文。构造顺序是：先放种子论文和它引用重叠最高的伙伴论文，再放两者的共享引用与并集引用，最后从该领域主要会议 2020 年之后的论文里采样，直到 5 万篇。人文领域因为开放获取论文少，只能到约 4 万篇。Table 1 里短答案题与开放式题的库大小并不相同：计算机科学 47,637 对 46,756，自然科学 50,000 对 48,879，医疗 50,000 对 47,745，人文 39,032 对 37,506。这说明两个题型各自过滤了一遍可用 PDF，不是共用同一个库；论文没有解释差异来源。`[已验证，Table 1；差异原因未写]`

语料里的每篇 PDF 用 PyMuPDF 转文本、PDFPlumber 转表格，得到 Markdown。稠密检索时只编码每篇的前 32,000 token，这是 gte-Qwen2-7B-instruct 的最大输入长度；BM25 索引全文。这个不对称是后面"BM25 更强"解释的一部分：长论文的证据如果落在 32,000 token 之后，稠密检索器根本看不到。`[已验证，§4.3]`

### 四、实验设置：同一 agent，换三种检索器

网页搜索实验用官方 API：GPT-5、GPT-5-mini、GPT-5-nano 的推理强度设为 medium，开启网页搜索；Gemini-2.5-Pro/Flash 的思考预算设为 -1（动态），给网页搜索权限；DR Tulu 部署在单张 H100 上，用 vLLM 推理（§4.1）。

语料搜索实验固定 DR Tulu 为 backbone。作者改它的 MCP 服务，让搜索工具只能调用指定的检索器，不能上网。三种检索器是 BM25（稀疏）、gte-Qwen2-7B-instruct（通用稠密）、ReasonIR（推理型稠密）。索引构建：下载全部 PDF、转 Markdown、编码前 32,000 token，batch size 为 1，单张 H100 算 embedding。DR Tulu 部署在两张 H100 上，一张跑 vLLM 生成，一张跑 MCP 检索。最大搜索轮数是 10，每轮返回 top-5 或 top-10 篇论文的标题和摘要（§4.3）。

### 五、结果：短答案 BM25 领先，开放式差距缩小

短答案题（Table 2，top-10）：BM25 81.2、gte-Qwen 63.0、ReasonIR 49.3；top-5 时分别是 75.8、46.9、38.7。BM25 对 gte-Qwen 的相对优势是 $81.2/63.0-1=28.9\%$，对 ReasonIR 是 $81.2/49.3-1=64.7\%$。摘要里的"约 30%"指前者，是相对百分比，不是 30 个绝对点；绝对差是 18.2 点。`[已验证，Table 2；口径需注明]`

开放式题（Table 2，top-10）：gte-Qwen 33.0、BM25 30.7、ReasonIR 26.2；top-5 时 26.0、25.5、17.3。BM25 不再领先，gte-Qwen 略高 2.3 点。作者的解释是开放式题允许多篇相关文档，稠密检索的语义泛化有优势；但差距很小，且没有置信区间。`[已验证，Table 2]`

网页搜索的对照（Table 2）：短答案 GPT-5 71.7、GPT-5-mini 62.3、GPT-5-nano 45.9、DR Tulu 42.0、Gemini-2.5-Pro 38.5、Gemini-2.5-Flash 38.0；开放式 GPT-5 26.3、GPT-5-nano 20.6、GPT-5-mini 20.4、DR Tulu 17.4、Gemini-2.5-Flash 16.0、Gemini-2.5-Pro 11.0。注意网页搜索与语料搜索不是同一个任务：前者要在开放网络里找，后者答案保证在 5 万篇语料里。BM25 的 81.2 高于 GPT-5 的 71.7，不能读成"BM25 比 GPT-5 强"，只能读成"闭域词面检索比开放网络搜索更容易"。`[已验证，Table 2；跨设置比较需注明]`

### 六、消融：搜索方法决定哪种信息重要

作者把短答案题拆成三个成分，逐个去掉，看 EM 的相对变化（Table 3）。网页搜索下：GPT-5 去掉元数据掉 24.45%、去掉细节掉 3.85%、去掉关系掉 16.92%；DR Tulu 掉 17.92%、21.60%、6.88%；Gemini-2.5-Pro 掉 11.43%、14.69%、5.67%。语料搜索下：DR Tulu + BM25 掉 8.17%、14.94%、24.59%；DR Tulu + ReasonIR 掉 5.33%、9.84%、15.99%。`[已验证，Table 3]`

这组数的读法是：网页搜索下，agent 最依赖图表细节（DR Tulu 掉 21.60%）；语料搜索下，agent 最依赖论文间关系（BM25 掉 24.59%）。原因是检索后端能提供什么，agent 就学会用什么：网页搜索能直接搜到论文页面里的图表描述，语料搜索的 BM25 对引用关系里的标题词更敏感。作者还发现，共用 Google Search 的 DR Tulu 与 Gemini-2.5-Pro 有相似的敏感模式，进一步支持"后端决定信息使用"的解释。这个发现比"BM25 更好"更有意思：它说明检索接口会塑造 agent 的查询策略。`[已验证，Table 3；解释是我的]`

### 七、语料级增强：把关键词放进文档开头

增强流程分两步。第一步抽元数据：出版会议、年份、作者、引用数。第二步用 Qwen3-Next-80B-A3B-Instruct 读每篇 Markdown 的前 20,000 字符，生成恰好 8 个主题关键词；提示词要求只返回逗号分隔的关键词（Fig. 13）。把这些字段拼成一段带强调的关键词袋，前置到每篇文档开头。这样 BM25 的倒排索引会把这些词当作文档内容，稠密检索器也会在输入开头看到它们。

结果（top-5，Table 4）：BM25 短答案 75.80→83.98（+8.18），开放式 25.52→27.25（+1.73）；gte-Qwen 46.90→47.80（+0.90），开放式 26.03→27.82（+1.79）；ReasonIR 38.70→40.40（+1.70），开放式 17.25→19.79（+2.54）。BM25 的增益最大，因为关键词直接进入词面匹配；稠密检索器的增益小，因为关键词被编码成语义向量后不再是硬约束，而且长文档的 32,000 token 截断仍然存在。`[已验证，Table 4]`

### 八、成本：只报了硬件，没报钱

论文报了部署：DR Tulu 用两张 H100，一张 vLLM 生成、一张 MCP 检索；稠密编码用单张 H100，batch size 为 1。没有报：索引构建的总 GPU 小时、20 万篇 PDF 的下载与转换时间、Qwen3-Next-80B 生成 8 个关键词的总调用量、每次查询的 token 与美元成本、BM25 与稠密检索的延迟对比。语料级增强的成本尤其关键：它要对 20 万篇论文各跑一次 80B 模型，语料更新时还要增量重跑；论文把这笔成本放在评测前，没有计入查询成本。`[系统问题]`

## Ideas

### 不足

**评估与统计**

1. 短答案题和开放式题都是 GPT-5-mini 生成的，没有人工校验，也没有标注者一致性。问题可能继承生成模型的偏好（例如偏爱某些句式、某些数字），答案的"唯一性"只由种子论文保证。`[评估问题]`
2. 短答案用 EM 判断答案是否出现在输出或引用里；开放式用加权召回，分子只算返回的相关文档，不惩罚无关文档。两个指标都奖励"多返回"：模型列出一长串论文标题，总有机会命中。Table 2 里 DR Tulu 平均返回 37.32 篇引用但 EM 只有 42.0，说明"多返回"不保证准，但指标没有惩罚它。`[评估问题]`
3. 主表没有置信区间，也没有重复运行。BM25 与 gte-Qwen 在开放式题上差 2.3 点，BM25 与 ReasonIR 在短答案上差 31.9 点；前者很可能落在噪声里，后者才值得解释。论文没有区分。`[评估问题]`
4. 网页搜索与语料搜索的对比不是受控实验：前者用开放网络，后者用 5 万篇固定语料；BM25 的 81.2 高于 GPT-5 的 71.7，只能说明闭域任务更容易，不能说明检索器更强。`[评估问题]`

**方法与归因**

5. 问题与语料同源：种子论文、它的引用网络、共享引用都被放进语料，问题又直接用这些信息生成。BM25 的词面匹配可能命中问题里的标题词、会议名、数字，而这些词在语料里正好高频。缺少"去掉标题/作者/会议等词面线索"的消融，无法判断 BM25 的优势有多少来自泄漏。`[方法问题]`
6. 稠密检索器只编码前 32,000 token，BM25 索引全文；SAGE 的论文平均 13,376 token，但长尾可能超过 32K。这个不对称会压低稠密检索器的分数。作者在 §A.4 讨论了 BrowseComp-Plus 的 4,096 token 截断，却没有对 SAGE 自己的 32K 截断做同样分析。`[方法问题]`
7. 论文没有写 gte-Qwen2-7B-instruct 与 ReasonIR 的调用方式：是否加了指令前缀（`Instruct: ... Query: ...`）、文档侧是否加 `Passage:` 前缀、是否按两个模型各自的最大输入长度截断。如果直接拿关键词串去编码，两个模型都在训练分布之外，分数会被系统性压低；这让"BM25 更强"多了一个替代解释。`[方法问题]`
8. "BM25 比 LLM-based 检索器高约 30%"是相对百分比（81.2 对 63.0），不是绝对点；摘要没有写口径，容易被读成 30 个点。`[评估问题]`
9. 行为分析主要在 DR Tulu 上做；SearchR1-32B 的补充实验只有 1.1–1.2 次搜索/题，接近单发，无法代表多轮 agent 的行为。作者在 Limitations 承认，但没有给第二套多轮 agent 的对照。`[方法问题]`
10. 语料级增强只测了"加 8 个关键词"这一种形式；没有测关键词数量、位置（开头/结尾/每段）、质量（人工 vs LLM）、元数据字段的消融。8 是拍的值，没有依据。`[方法问题]`
11. 开放式题的增益很小，作者归因于查询分解多样性低，但没有直接测"查询覆盖了多少标准答案文档"；如果 agent 只查了 1–2 个角度，语料增强当然无法提升召回。`[方法问题]`

**系统与成本**

12. 没有报索引构建、语料转换、关键词生成、查询的 GPU 小时与美元成本；20 万篇 × 80B 模型的关键词生成是一笔大开销，语料更新时还要重跑。`[系统问题]`
13. 没有报检索延迟、p50/p99、BM25 与稠密的吞吐对比；agent 的端到端延迟受检索轮数与每轮延迟共同影响，论文只给了轮数。`[系统问题]`
14. 每个领域只有约 5 万篇论文（人文约 4 万），远小于真实学术搜索引擎；BM25 在 5 万篇上线性扫描的代价还可以接受，扩大到千万篇时结论可能变。`[系统问题]`
15. 短答案与开放式的库大小不同（Table 1），论文没有解释是过滤、去重还是可用 PDF 差异；这会影响两个题型的可比性。`[系统问题]`

**内部矛盾**

16. 摘要说"BM25 significantly outperforms LLM-based retrievers by approximately 30%"，正文 Table 2 的开放式题上 BM25 并不领先（30.7 对 gte-Qwen 33.0）；这个结论只在短答案题上成立。`[评估问题]`
17. 摘要说语料级增强"yields 8% and 2% gains"；Table 4 的 8.18 与 1.73 都是绝对点（EM 与加权召回），不是相对 8%/2%。`[评估问题]`
18. §3.4 说"每个领域构造 5 万篇语料"，Table 1 的短答案与开放式库大小都不到 5 万（人文约 3.9 万/3.75 万）；数字对不上，原因未写。`[系统问题]`

### 创新点

**一、去泄漏消融：把问题里的词面线索拿掉**

- **主张**：SAGE 的短答案题里含大量标题、会议、作者、数字线索，BM25 可以直接匹配；把这些线索改写成不含专有名词的语义描述，BM25 相对稠密检索器的优势会显著缩小。
- **与原文关系**：反驳/修正。原文把 BM25 的优势归因于"查询-检索器错配"，但问题本身的词面化也是原因。
- **最小验证**：从 600 道短答案题里选 200 道，用 GPT-5-mini 把问题改写成"不含论文标题、作者、会议名、具体数字"的版本，人工核验改写后仍唯一可解；在同一 DR Tulu + BM25/gte-Qwen 设置下比较 EM。预期 BM25 的绝对分下降，BM25 与 gte-Qwen 的差距从 18.2 点缩到 10 点以内。
- **失败条件**：改写后 BM25 仍领先 18 点以上，或改写后问题不再唯一可解、无法评测。这说明词面线索不是主因，错配解释成立。

**二、长文档的分层稠密编码，消除 32K 截断**

- **主张**：SAGE 的稠密检索器只编码前 32,000 token，长论文的后半部分证据丢失；用段落级编码 + 晚交互（late interaction）或分层摘要，能在不增加索引成本太多的前提下，让稠密检索器看到全文。
- **与原文关系**：增量，直接针对 §A.4 提到的截断不对称。
- **最小验证**：在 SAGE 的 20 万篇语料上，比较三种索引：前 32K 编码（原文）、全文分段编码 + 最大段分数、全文分段编码 + ColBERT 式晚交互；在短答案题上比较 EM 与索引构建时间。预期分段编码把 gte-Qwen 的 EM 从 63.0 拉到 70 以上，缩小与 BM25 的差距。
- **失败条件**：分段编码的提升小于 3 点，或索引成本超过 BM25 的 10 倍。这说明截断不是主因，或者长文档的稠密编码本身不划算。

**三、retriever-aware 的查询改写**

- **主张**：既然 agent 的子查询是关键词式的，而稠密检索器需要自然语言，那么在查询进入检索器前加一层轻量改写（把关键词串扩成完整问句），能让稠密检索器在 agent 工作流里追上 BM25。
- **与原文关系**：扩展。原文的 Limitations 提到"训练 agent 适应检索器"，但没有做；这条线用推理时改写代替训练。
- **最小验证**：在 DR Tulu + gte-Qwen 的设置里，对每个子查询用一个小模型（如 Qwen3-8B）扩写成自然语言问句，再检索；比较短答案 EM、开放式加权召回、每轮延迟。预期 gte-Qwen 的 EM 从 63.0 升到 70 以上，延迟增加不超过 20%。
- **失败条件**：改写后 gte-Qwen 仍低于 BM25，或改写引入语义漂移、准确率下降。这说明错配不是查询形式的问题，而是稠密编码在长文档上的固有限制。

**四、语料级增强的成本账本**

- **主张**：语料级增强的收益必须用"每篇文档的生成成本 + 索引重建成本"来折算；如果每提升 1 个 EM 点要花超过某个阈值的钱，它就不适合在线服务，只适合离线一次性构建。
- **与原文关系**：正交。原文只报收益，不报成本。
- **最小验证**：记录 20 万篇论文的 PDF 下载、Markdown 转换、8 关键词生成（Qwen3-Next-80B）的 GPU 小时与美元；按"每次语料更新重跑增量"和"全量重跑"两种策略，算每 1,000 次查询的摊销成本；与"不增强 + 更大 top-k"的基线比较。预期增强的摊销成本高于把 top-k 从 10 提到 20，但低于换一个更大的稠密检索器。
- **失败条件**：增强的成本高于收益，或语料更新频率让摊销成本失控。这时"增强语料"不如"增强查询"或"换检索器"。

**五、混合检索：BM25 与稠密的分数融合，按查询类型路由**

- **主张**：BM25 在短答案、关键词式查询上强，稠密在开放式、语义泛化上强；把两者的分数融合（如 reciprocal rank fusion），或按查询类型路由，能同时拿到两边的优势。
- **与原文关系**：正交。原文把两者当替代关系比较，没有测组合。
- **最小验证**：在 SAGE 的 1,200 题上，比较 BM25、gte-Qwen、RRF 融合、按"查询是否含年份/会议/数字"路由四种策略；指标是短答案 EM、开放式加权召回、每轮延迟。预期融合在短答案上接近 BM25，在开放式上超过 gte-Qwen。
- **失败条件**：融合被任一单检索器支配，或路由规则在跨领域时失效。这说明两种检索器的优势不是互补的，或者查询类型难以自动判断。

**六、跨论文：把 SAGE 的语料增强接进 A-RAG 与 DCI**

- **主张**：A-RAG 的 `keyword_search` 与 DCI 的 `grep` 都依赖词面匹配；把 SAGE 的元数据与关键词前置到语料文件开头，能让这两个系统的关键词工具在科学文献任务上召回更高，而不改它们的 agent 循环。
- **与原文关系**：正交，组合三篇论文的机制。
- **最小验证**：在 SAGE 的 5 万篇子集上，分别跑 A-RAG（keyword + semantic + chunk read）与 DCI（bash + grep），比较增强前后的短答案 EM、检索 token、工具调用。预期 A-RAG 提升 3–6 点，DCI 提升 5–10 点。
- **失败条件**：增强后没有提升，或前置关键词让 chunk 边界与语义检索变差、准确率下降。这说明增强只对 BM25 有效，不能迁移到 agentic 接口。

## 相关工作

仓库内与本文最接近的是 [du2026-a-rag](du2026-a-rag.md)：两者都在研究"agent 怎么检索"，但 A-RAG 把检索接口做成三层工具，让模型自选粒度；SAGE 固定 agent 的接口，只换背后的检索器，研究"哪种检索器适合 agent 生成的查询"。A-RAG 的 `keyword_search` 正是 SAGE 证明有效的那类词面接口，SAGE 的结论可以解释 A-RAG 为什么要保留关键词工具。

[li2026-dci](li2026-dci.md) 把检索器整个去掉，让 agent 用 `grep` 直接读语料；SAGE 的"BM25 强于稠密"与 DCI 的"词面匹配强于语义相似度"是同向证据，但 DCI 更激进：连 BM25 的倒排索引都不要，直接扫文件。SAGE 的语料级增强如果接到 DCI，就是"给文件加关键词头"，与 DCI 的"原始语料"理念有张力。

[wan2026-decision-rag](wan2026-decision-rag.md) 用决策模型逐层选分支，SAGE 用 BM25 做词面召回；前者把选择做成判断，后者把选择交给词频。两者可以组合：BM25 负责粗召回，决策模型负责在候选里选。

[kumar2026-stair](kumar2026-stair.md) 用目录叶节点当检索单位，SAGE 用论文全文当检索单位；前者依赖结构，后者依赖长文档编码。SAGE 的 32K 截断问题在 STAIR 里不存在，因为叶标题很短；但 STAIR 需要目录，SAGE 的语料没有统一目录。

[bao2026-raw-rag](bao2026-raw-rag.md) 的结论是"配好的原始检索比复杂记忆系统更强"，SAGE 的结论是"配好的 BM25 比 LLM 检索器更强"；两篇都在用强基线重设参照系，提醒读者不要默认"更复杂的语义模型更好"。

[he2026-memory-tax](he2026-memory-tax.md) 的收益/税账本可以补 SAGE 缺的成本维度：语料级增强的收益（+8.18 EM）要减去 20 万篇论文的关键词生成成本。

## 可复现

- 代码与数据：<https://github.com/HughieHu/Sage>（首页给出）。
- 数据规模：1,200 题（4 域 × 150 短答案 + 150 开放式）；语料约 20 万篇开放获取论文，每域约 5 万（人文约 4 万）；短答案平均 1 篇标准答案，开放式平均 9.94–17.62 篇。
- 模型：DR Tulu（单/双 H100，vLLM）；GPT-5、GPT-5-mini、GPT-5-nano（推理强度 medium，开网页搜索）；Gemini-2.5-Pro/Flash（thinkingBudget=-1，开网页搜索）；关键词生成用 Qwen3-Next-80B-A3B-Instruct；问题生成用 GPT-5-mini。
