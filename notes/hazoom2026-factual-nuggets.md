# Iterate Until Retrieved: Factual Nugget Optimization for Discoverable Continual Corrections in Agentic RAG

## Why

企业知识助手每天都在收反馈。用户点"没帮助"、在评论区补一句"其实是这样"、或者直接指出答案错在哪。这些反馈大部分没法用：有的是"不够有用"这种空话，有的是对语气的意见，有的只对当前这轮对话成立。但有**一小部分**说了一件可以复用的事实——某个版本的某个角色不能重置别人的密码、某个集成在某种配置下会失败。论文把这种反馈叫**可操作的事实更正**（actionable factual correction），并把由它写成的一条短知识库条目叫**事实碎片**（factual nugget）（§1、§3.2）。

问题不在"把这句话总结下来"。把更正写成一段文字是容易的，难的是让**未来的查询能找到它**。未来提问的人角色不同、措辞不同、用的是公司内部词汇，与原始反馈的字面重叠可能极少。而这条碎片要放进一个中位数约 45 万篇文档、最大到几百万篇的客户语料里（§3.1），与大量语义邻近的文档竞争同一个检索位。论文报告，标准做法（把碎片原样入库）在留出的真实历史查询上只有 52.3% 的检索率、41.3% 的引用率（Table 1）。也就是说，事实写对了，但一半的时候根本没被捞出来。

现有三类做法各有缺口。**文档扩展**（document expansion）给文档补合成查询或相关文本，理论上正对这个病；但被引用的 Weller et al. 2024 显示，扩展的效果依方法、检索器、数据集而变，甚至会掉分（§2）。也就是说，"多写几句同义词"不是稳赚的事，必须对着真实检索栈验证。**LLM 记忆**把过去的交互改写成自包含记忆，但那些方法面向用户的私有情节记忆，存的是"用户说过什么"，不是"公司知识里哪一条是错的"；而且它们通常不做下游验证（§2）。**反馈驱动的知识库更新**里，PatchRAG 假设反馈本身就是一份完整正确答案，存进一个平行的反馈记忆，且在学术基准上做合成反馈；STACKFEED 直接改知识库文档，需要专家或预言机给出反馈（§2）。这两条路在本文的部署约束下都不合用：客户文档是客户的所有权与事实来源，就地改一句话会破坏多步流程的连贯性，也无法在全库范围验证。

为什么现在必须解决：这类助手的语料规模决定了"入库即被发现"不成立，而反馈是**连续**来的。如果每一条更正都需要人来判断"这条能不能被检索到"，成本会随反馈量线性增长；如果不管，用户已经明确告诉你错了，系统却仍然答错，这是最伤信任的一种失败。

于是问题落到这里：能不能在**不改动生产 agent 任何配置**的前提下，把每条事实碎片优化到"能被未来的不同问法检索到并被引用"？以及，这种优化在真实生产流量上还剩多少收益、代价是多少？

## What

论文的答案是：能，而且收益主要来自"把碎片当可检索物去优化"而不是"把碎片写得更完整"。方法叫 INO（Iterative Nugget Optimization，迭代碎片优化）：把生产 agentic RAG 当成测试台，先用更正写一条初始碎片，用触发查询加若干改写去探测它，检索失败就检查"谁排在它前面、答案被带成什么样"，据此改写碎片的标题、正文与检索锚点，最多三轮，直到它在探针集上被检索并引用（§4-E、Algorithm 1）。在 100 条真实反馈碎片、410 条留出查询上，检索率从 52.3% 升到 77.3%、引用率从 41.3% 升到 68.1%（Table 1 的历史查询子集）；在 160 条工单样本上从 35.1% 升到 78.2%（Table 3）。

先把任务说清楚。输入是一条通过可操作性过滤的反馈（含原始问题 $q_0$、被反馈的答案、自由文本更正）与目标客户的语料。输出是一条可索引的碎片 $n^\star$：标题、一到三句正文、可选的检索锚点。它必须满足两条：在 $q_0$ 与若干**没参与构造**的改写查询上被检索到（过重排器）、并被最终答案引用。边界是：生产 agentic RAG 栈完全固定（提示词、超参、工具、配置都不动），每条碎片只改自己的内容；客户语料有中位数约 45 万篇文档；评测是英语。

### 新认识：真正的瓶颈是"被发现"，不是"写对"

第一个认识是**正确性与可检索性可以完全脱钩**。标准做法（变体 A）的碎片内容就是从反馈里抽出来的正确事实，它的问题不是写错，而是写得太窄：与原始交互的措辞绑在一起，未来用户的问法一换就捞不到（§1、§4-A）。Table 1 的数字把这个脱钩量化了：同一批正确的事实，检索率 52.3%，也就是说近一半的正确答案躺在库里但没进上下文。`[已验证]`

第二个认识是**盲目的文档扩展有天花板，必须闭环验证**。变体 B 加一句触发查询的改写（检索 67.0%），变体 C 加五条合成查询（67.8%），变体 D 两者合并（72.9%），提升是单调的，但每一步都卡在"猜未来会怎么问"。INO 从 D 出发，用真实检索栈跑探针、看失败原因再改，把历史查询上的检索率推到 77.3%（Table 1）。这说明扩展能解决一部分词汇不匹配，剩下的部分要靠**看到谁排在前面**才能改——这是文本层面看不到的信息，只有跑一遍检索才有。`[已验证：A→D 与 D→E 的对比]`

第三个认识是**优化对象的选择本身就决定了成本结构**。提示词优化器通过改指令或上下文，把一次改动摊到很多未来任务上；INO 反过来，把工作量摊到"关于同一条更正的很多未来查询"上，改的是**可检索的那份产物**（§1）。这个选择的直接后果是：生产 agent 配置不动，所以改动是局部的、可审计的、可按碎片回滚；代价是这个循环要为每条碎片各跑一次，不能让一次优化服务所有碎片。`[宣称；成本数据支持"每条约 111 秒、0.31 美元"]`

### 新方法：一个闭环 + 五个变体

第一样方法是**可操作性过滤**。一个 LLM 一次调用同时做分类与抽取：输入是对话历史、最终问题、被反馈的答案、反馈类型、自由文本、当前轮引用的文档；输出是 JSON，含"有用性标签""这条反馈能否产出事实碎片""简短理由"，以及可产出时的标题与正文（§A）。生产切片上，聊天 agent 的可操作率是 42.3%，工单转写 agent 是 21.5%（5,000 条事件）；在 200 条人工标注上，分类器与裁决标签的一致率是 96.7%（§3.1、§D）。`[§3.1、§D]`

第二样方法是**碎片作为独立的可索引单元**。一条碎片有标题、一到三句正文、可选的检索锚点；它不修改客户文档，而是作为一条辅助条目插入语料。论文给了两条理由：客户文档通常覆盖较宽的流程，而反馈只涉及其中一个窄细节；就地改一句话会改变多步流程的连贯性，且无法在全库验证（§3.2）。发布与创建分离：碎片在客户管理员或知识负责人批准前不入库，但可以配置为自动发布；每条碎片保留来源（反馈事件、触发查询、修正后的答案、时间戳、客户、负责人），便于审计。`[§3.2]`

第三样方法是**五个构造变体**，它们构成一条从"不优化"到"闭环优化"的阶梯：

| 变体 | 做法 | 检索锚点 |
| --- | --- | --- |
| A | 标准碎片：原样入库 | 无 |
| B | 触发查询锚点：追加一句 $q_0$ 的改写 | 1 条 |
| C | 合成锚点：让 LLM 写 5 条未来可能的问题 | 5 条 |
| D | B + C：1 条 $q_0$ 改写 + 4 条其他问法 | 5 条 |
| E | INO：从 D 出发，用生产栈跑探针并改写 | 动态 |

第四样方法是**INO 的循环**。探针集固定为 4 到 6 条：$q_0$ 加 3 到 5 条为这次评测**新生成**的改写；这些探针与塞进碎片里的锚点**故意不重叠**——锚点在文档内当检索钩子，探针在文档外检验泛化（§4-E）。判定条件 `PASS(n*, q)` 是"该碎片对查询 $q$ 既被检索到又被引用"。每轮把失败的探针、它检索到的竞争者、生成的答案与当前碎片一起给反射器，反射器改写标题、正文措辞与锚点，但被明确要求**不得新增事实**。改完重新入库、重测，最多 $T=3$ 轮（Algorithm 1）。实测收敛分布：56% 的碎片第一轮就过，32% 第二轮，12% 需要第三轮，没有碎片耗尽预算仍未过（§5）。

### 新结论：三层指标都在涨，但涨幅随查询来源变化很大

**留出查询（聊天 agent，410 条）。** 历史真实查询 110 条上，A 到 E 的检索率是 52.3 → 67.0 → 67.8 → 72.9 → 77.3，引用率是 41.3 → 50.7 → 52.0 → 58.9 → 68.1。LLM 改写的那 300 条上，检索率 64.1 → 76.1 → 86.4 → 89.4 → 93.7，引用率 57.3 → 68.5 → 77.0 → 81.5 → 86.1（Table 1）。同一批碎片在合成改写上比真实历史查询高 12 到 20 个百分点，作者据此把历史子集称为"更保守的现场估计"（§6）。`[已验证，三次运行]`

**原始触发查询（100 条，样本内）。** 检索率 67.6 → 79.1 → 88.0 → 90.8 → 97.0，引用率 60.2 → 71.8 → 79.5 → 81.9 → 89.1（Table 2）。`[已验证]`

**工单 agent（160 条）。** 基线只有 35.1% 的检索率；A 到 E 是 35.1 → 42.0 → 48.8 → 63.3 → 78.2，引用率 29.7 → 37.8 → 44.2 → 58.5 → 70.4（Table 3）。作者把更大的涨幅归因于输入更难：工单是多轮转写，含填充语、多个问题、与原更正不同的词汇（§6.1）。`[已验证]`

**答案层。** 用 LLM 裁判在四个维度上打分：更正遵从度、对碎片的忠实度、非回退、接地性。INO 让答案"实质反映更正"的比例从 52.2% 升到 73.4%（McNemar $p\approx0.003$）；没检索到碎片的比例从 40% 降到 13%（按 Table 1 的 110/300 条加权复算，基线约 39.1%、INO 约 10.7%，与正文的 40%/13% 差 2.3 个百分点，原文未说明这两个数用的是哪一批查询）；在检索到碎片的条件下，忠实使用碎片的比例从 54.1% 升到 81%；重大回退从 15.6% 降到 11.6%，被判为"编造接地"的比例从 19.1% 降到 14.8%（§6.3、Fig. 3）。`[已验证；裁判经过人工校准，见 How]`

**负样本。** 1,400 条随机客户查询里，20 条（1.4%）检索到了新插入的碎片，12 条（0.8%）引用了它；人工检查这 20 条，没有发现误报，每一条都是同一话题的等价改写恰好出现在随机样本里（§6.2）。`[已验证，人工检查但未报第二位标注者]`

**线上。** 对随机 20% 的用户隐藏碎片五天，与前移七天的同一窗口做双重差分（difference-in-differences，DiD），点赞倾向下降 11.44%（$p=0.055$）（§6.4）。`[已验证但边缘显著；p 大于 0.05]`

**代价。** 变体 A 到 D 约 0.012 到 0.0124 美元、12.9 秒；INO 额外 0.30 美元、98.3 秒，合计约 0.31 美元、111.2 秒每条。这笔钱在索引时一次性付，之后不增加查询延迟（§E）。`[已验证]`

## How

判型：以**系统与算法类**为主，附**实证与基准类**。系统与算法类指索引时优化循环（探针设计、判定条件、反思器约束）与"碎片作为可索引单元"的设计；实证与基准类指 100 条真实反馈、410 条留出查询、160 条工单样本、LLM 裁判校准与线上 DiD。没有新模型、没有训练。

### 一、生产约束决定了方法形状

两个 agent：一个回答自由形式的支持问题（客户知识库），一个读工单转写并建议回复。每个客户有独立语料与独立 agent 配置；语料中位数约 45 万篇文档，最大几百万篇（§3.1）。这组数字解释了两件事：第一，新增一条文档必须"抢"检索位，光靠语义相关不够；第二，任何把改动摊到全库的方案（重建索引、改提示词）都不现实，只能按条改。

检索栈是固定的：查询生成器加基于中间结果的迭代检索；混合检索（在专有域数据上微调过的稠密向量 + 稀疏表示，例如 BM25）；微调过的交叉编码重排器；重排分数经一个小 MLP 校准到 $[0,1]$，超过置信阈值的文档才进生成器；重排前取 top-$k=60$。论文强调：**所有变体之间唯一改变的产物就是新插入碎片的內容**（§3.3）。这句话是整篇论文可比性的基础——如果换了检索栈或提示词，A 到 E 的差异就不能归给碎片构造。

### 二、为什么新建碎片而不改客户文档

两个理由都写在 §3.2。第一，客户文档是宽流程的事实来源，反馈通常只涉及其中一个窄细节，改文档等于把一个局部修正塞进一份更大的叙述里。第二，局部就地编辑难以全局验证：改一句话可能让一个多步流程前后矛盾，而现有工具没法自动检查这种连贯性。

把碎片做成**原子、辅助、可撤销**的条目，代价是引入"碎片与源文档可能冲突"这个新问题；论文的应对是范围限定——例如一条限定到 "portal v8.2" 的碎片在版本更新后对超范围查询自然失效（§3.2）。这是设计上的自洽，但也把问题推给了后续（见 Ideas 第八条）。

### 三、INO 循环的每一步

输入是一条碎片 $n$ 与触发查询 $q_0$。第一步 `INITIALEXPANSION` 生成变体 D 的形态（$q_0$ 的非逐字改写 + 四条其他问法）。第二步固定探针集 $Q=\{q_0\}\cup\text{PARAPHRASE}(q_0)$，共 4 到 6 条。第三步进入最多三轮的循环：入库；对每条探针跑 RAG，把"未通过"的探针与它的检索和答案轨迹收进 $F$；若 $F$ 为空就提前退出（保持已入库状态）；否则先出库，再让反射器基于 $F$ 与 $q_0$ 改写。

反射器的输入有五样：当前碎片、触发查询、失败的探针、失败探针的 top 竞争者文档、生成的答案。提示词有三条硬约束：不得增加更正与给定上下文之外的新事实；可以增加术语、澄清范围、改写锚点；目标是让更正**更容易被发现**（§A）。

这一步的实际效果在 §6.5 的例子最清楚。原始碎片叫"portal v8.2 中的密码重置角色限制"，正文说"只有 Workspace Owner 能从管理面板重置别人的密码，Analyst 只能查看"。一条探针"user reset isn't working for my team lead"没过——一篇泛泛的"重置你自己的密码"文章靠 reset 与 isn't working 这两个词排在前面。反射器看到竞争者后做了三处改动：标题加上"for other users"；正文补一句"该限制不适用于用户从登录页重置自己的密码"；锚点里加一条"重置他人密码 vs 重置自己的密码"。这四处改动都不是新事实，而是**把区分度写进文本**。下一轮全部通过。

### 四、为什么探针要和锚点分开

这是方法里最容易做错的一处。如果探针就是塞进碎片的那些锚点，那么"检索到"是构造出来的，等于自己出题自己答。论文的做法是：锚点在文档内（当检索钩子），探针在文档外（检验泛化），而且探针是为这次评测新生成的，与锚点不重叠（§4-E）。这个设计让 INO 至少不能直接把自己写进去的字符串背回来。

不过它仍有上限：探针只有 4 到 6 条，而且是同一个 LLM 从同一个 $q_0$ 生成的改写，与锚点共享同一个"改写分布"。这一点在样本内与留出的差距上看得见（97.0% 对 77.3%），见 Ideas 第二条。

### 五、评测三层与裁判校准

第一层**检索**：碎片过了重排器、进了生成器可见的上下文。第二层**引用**：碎片出现在最终答案的来源里。第三层**答案遵从度**：LLM 裁判看原始问题、原始答案、用户反馈、抽出的碎片、检索上下文与新答案，在四个维度上打标签——遵从度（addresses / partial / misses / contradicts）、对碎片的忠实度（faithful / partial / unfaithful，碎片不在上下文则为 N/A）、非回退（preserved / minor / major）、接地性（grounded / minor issues / hallucinated）。 rubric 锚定在用户的更正上，因为生产数据没有金标准答案（§6.3、§C）。

校准做了两步：100 条裁判决策由三位内部标注者独立标注，各维度的 Fleiss $\kappa$ 都超过 0.75；以多数票为裁决标签，裁判与裁决的 Cohen $\kappa$ 在"小幅提示校准"之后每个维度都超过 0.80（§6.3）。这里有一个需要留意的细节：校准与报告用的是同一批 100 条决策，没有留出校准集，因此 0.80 是乐观估计（见 Ideas 第四条）。

线上研究用 DiD：随机 20% 用户隐藏碎片，五天窗口，对照是前移七天的同一窗口，只保留"碎片检索倾向高"的查询，比较点赞倾向（§6.4）。

### 六、开销

变体 A 到 D 的成本几乎全在抽取上（0.012 到 0.0124 美元、12.9 秒）；INO 的额外成本在探针跑批与三轮反射（+0.30 美元、+98.3 秒）。作者给了一个降级建议：预算紧时用变体 D，在留出聊天查询上能到 84.8% 检索 / 75.1% 引用，成本只有 INO 的约二十五分之一（§E）。这两个数按 110 条历史与 300 条改写加权复算基本对得上：$(110\times72.9+300\times89.4)/410\approx85.0$、$(110\times58.9+300\times81.5)/410\approx75.4$，比文中各高 0.2 到 0.3 个百分点；原文没有说明 $84.8/75.1$ 用的是哪种聚合口径。

### 七、边界

四条，前三条作者自己列：只有一个检索架构（纯稠密、纯稀疏、迟交互可能对锚点反应不同）；只有英语；抽取、锚点、反射、裁判全用前沿 LLM，没有做模型消融。第四条是我加的：碎片是新写入的权威样式文档，它的过期与冲突没有测（作者把它划到范围外）。

## Ideas

### 不足

1. **没有长度或锚点数量的匹配对照**（方法问题）。A 到 E 的提升同时伴随文本变长：A 只有正文，B 加一句，C 加五条，D 加五条更针对的，E 再加改写。一条短文档在一个 45 万篇的语料里本来就更难被召回，加任何相关文字都会提升词面与语义匹配。论文没有"加同样多的、与失败探针无关的通用领域词"这一档对照，因此"INO 的优化"与"多写几句"没有分开。被引用的 Weller et al. 2024 恰恰说明扩展可能掉分，这让"这里的扩展单调有益"更需要一个长度对照来解释。

2. **探针集固定且很小，样本内与留出的 20 点差距就是过拟合的直接读数**（方法问题）。INO 在 100 条触发查询上到 97.0%，在 110 条真实历史查询上只有 77.3%（Table 1 与 Table 2）。也就是说，循环把碎片调到"这 4 到 6 条探针能过"，其中相当一部分收益不能迁移到晚到的不同问法。论文没有报告"探针数与留出性能"的关系，也没有把探针分成优化集与选择集——反射器每轮看到的都是同一批探针，等于在同一份小验证集上早停。

3. **"历史真实查询"是用相似度筛出来的近邻，不是随机流量**（评估问题）。构造方式是对五个月生产查询建 FAISS，取 top-50 近邻，保留余弦相似度高于 0.75 的，再用重排器筛到高于 0.85（§B）。这意味着 110 条"历史"是**与触发查询最像**的那批查询。它们比随机流量容易得多，所以 77.3% 是现场表现的上界而不是估计。作者自己说真实查询"最多比合成改写低 25 点"，但这句话里的"真实"仍然是筛选过的真实。

4. **裁判与校准存在循环**（评估问题）。裁判看得到抽出的碎片，而"对碎片的忠实度"与"更正遵从度"都在问"答案是否反映了这条碎片/这条更正"；INO 产出的碎片更长、更明确、措辞与更正更贴近，这两项会机械地变好。加上校准与报告共用同一批 100 条决策（Cohen $\kappa$ 0.80 是样本内数字），裁判的可信度没有独立验证。要分开，需要一个不看碎片的裁判（只看问题与原始反馈）或人工盲评。

5. **负样本的解释偏乐观**（评估问题）。1,400 条随机查询里 1.4% 检索到新碎片，人工检查"没有误报"，理由是每条都是同话题的等价改写。但如果随机样本里本来就混进了同话题查询，那么 1.4% 衡量的是话题重叠率，不是过度召回率。真正需要的是"异话题查询被召回"的比例，而论文没有按话题分层抽样，也没报第二位标注者的一致性。

6. **线上实验是边缘显著，且对照不是同期**（评估问题）。$p=0.055$ 大于 0.05；对照窗口是前移七天而不是并行的对照组；只保留"碎片检索倾向高"的查询；11.44% 是相对下降，没有置信区间。七天窗口还混着内容更新、季节性与用户构成变化。作者把它写成"改善用户满意度"，证据强度撑不住这个措辞，更准确的说法是"与满意度正相关、方向一致、未达常规显著水平"。

7. **四个 LLM 环节叠在一起，没有拆开**（系统问题）。抽取、锚点生成、反射、裁判各调一次前沿模型；其中只有抽取明确写了型号（GPT-5.2，中等推理），留出查询的合成改写明确用了 GPT-5.4 高推理，锚点生成、反射与裁判的模型在正文里没有点名。论文承认没做模型消融。后果是：报告的效果属于"整条 LLM 流水线"，换一个更弱的模型，锚点质量与反射质量都会变，而这两个环节恰恰是方法的核心。至少应当报"用同一模型做锚点与反射"和"换成小模型"两档。

8. **过期与冲突只靠范围限定兜底**（数据问题）。碎片限定到 "portal v8.2" 可以自然失效，但如果一条新更正与一条旧碎片都限定在同一版本、内容相反，系统会同时检索到两条，答案可能自相矛盾。论文把"管理演化语料里的过期"列为范围外（§3.2）。这是这套设计最现实的运维风险：碎片越容易被检索到，冲突碎片也越容易被一起检索到。

### 创新点

**一、给"优化"配一个长度与内容双匹配的安慰剂对照**

- 主张：把"多写锚点"与"对着失败改锚点"分开。安慰剂组加入同样数量的、从客户语料随机抽的领域短语，不针对任何失败探针；如果安慰剂也能拿到大部分提升，说明收益来自长度而非优化。
- 与原文关系：反驳（原文把 A→D→E 的单调提升解释为优化递进，未排除长度效应）。
- 最小验证：在 100 条碎片上加安慰剂变体（与 D 同长度、锚点随机），跑同样的 410 条留出查询。判据是安慰剂的检索率显著低于 D 与 E，且与 A 的差距小于 D 与 A 的差距的一半。
- 失败条件：安慰剂接近 D（差距小于 2 点），说明"加相关领域词"就够，INO 的闭环价值需要重新论证。

**二、把探针分成优化集与选择集，报"探针过拟合"曲线**

- 主张：探针过拟合可以被测量并被控制。做法是把 10 到 12 条探针切成两半：一半给反射器看，另一半只用于选轮次；再报告"探针集大小 → 留出检索率"的曲线。
- 与原文关系：增量 + 反驳（原文在同一批 4 到 6 条探针上迭代并早停）。
- 最小验证：在 100 条碎片上跑三种配置（4–6 条探针不分割、4–6 条分割、10–12 条分割），比较 110 条真实历史查询上的检索率与轮次分布。判据是分割后留出检索率提升 3 点以上，且轮次分布更分散。
- 失败条件：分割后留出性能反而下降（因为可用探针变少），说明探针数才是瓶颈，此时应扩探针而不是分割。

**三、为碎片加事实漂移校验器**

- 主张：反射器"不得新增事实"目前只是提示词约束，没有测量。应当用一个独立的校验器把碎片里的每个断言与反馈文本、源文档比对，输出漂移率；漂移率高的碎片在发布前拒收。
- 与原文关系：正交（补一个安全维度，原文只报检索与引用）。
- 最小验证：用现成的 100 条碎片与三轮改写记录，请人类标注者判断"改写是否引入了反馈之外的事实"，统计比例；再训练或提示一个校验器复现该判断。判据是人工漂移率显著大于零，而校验器能把它识别到 90% 以上。
- 失败条件：人工漂移率接近零（提示词约束确实有效），那么这条主张降级为"应报一个零漂移的证据"，校验器可以不做。

**四、用随机流量而不是相似度筛选的查询做留出**

- 主张：现场估计必须用未经相似度筛选的查询。构造方式是：对每个客户，从五个月流量里随机抽查询（排除与 $q_0$ 的相似度前 5%），再看碎片是否被检索并被答案引用；同时按话题分层报"同话题 / 异话题"两组。
- 与原文关系：反驳（原文的"历史真实查询"是 top-50 近邻里筛出来的，偏易）。
- 最小验证：同一批碎片在随机流量与现有历史子集上各算一遍检索率与引用率，报差值。判据是随机流量的检索率比历史子集低 10 点以上。
- 失败条件：两组差值小于 3 点，说明相似度筛选没有带来实质偏差，现有估计可以保留。

**五、把碎片做成有生命周期的条目：过期、覆盖与冲突检测**

- 主张：碎片越容易被检索到，错误碎片与过期碎片的危害越大。应当给碎片加版本范围与有效期，并在写入时检测"与现有碎片是否矛盾"，冲突时要求人工裁决；同时监测"过期碎片仍被检索"的比例。
- 与原文关系：扩展（作者把过期划到范围外，但这是上线后的主要风险）。
- 最小验证：在现有 100 条碎片上人为制造版本升级（把 v8.2 改成 v9.0），看旧碎片还被打捞的比例；再构造 20 对内容矛盾的碎片，看答案是否同时引用两者。判据是旧碎片打捞率显著大于零且冲突对引出矛盾答案。
- 失败条件：版本限定本身就足以让旧碎片失效（打捞率接近零），说明现有设计够用，只需加一个监控指标。

## 相关工作

与 [T-Mem](guo2026-t-mem.md) 都在"写入时决定怎么组织"，对象不同：T-Mem 把对话写成带类型的记忆并用触发器索引，问的时候按触发器召回；INO 把一条更正写成可检索的碎片，用生产检索栈反复试。两者的共同点是"写入时为读服务"，区别是 INO 把验证也放在写入时——碎片必须当场通过检索与引用检查。

与 [Jev-Mem](jiang2026-jev-mem.md) 的位置不同：Jev-Mem 在读取时控制"要不要查、查哪条线、查多深"，把成本压在查询侧；INO 不动查询侧，把成本压在写入侧（每条 111 秒、0.31 美元），换来零查询延迟。这两种成本结构适用于不同流量形态：查询多、更正少时，写入侧付费更划算。

与 [RAW-RAG](bao2026-raw-rag.md) 的关系是"参照系"：RAW-RAG 说明配好的原始检索很强，记忆系统的增益要先跨过这条线。INO 没有和记忆系统比，它比的是同一检索栈下碎片的四种写法——这是一个更窄但更干净的对照，因为检索栈完全相同，唯一变量是产物内容。

与 [SAGE](hu2026-sage.md) 都在处理"检索到不到"的问题，层次不同：SAGE 在固定语料上比较检索器与语料级增强，发现 BM25 在短答案上强于某些稠密检索器；INO 在固定检索器上改被检索的文档。SAGE 的结论恰好解释了 INO 为什么有效——短碎片在混合检索里靠词面匹配赢，所以把"区分度词"写进去（如 "another user's"）就能改变排序。

与 [IRAH](cardei2026-irah.md) 是同一枚硬币的两面：IRAH 优化**流水线配置**（切块、编码器、重排器、$k$、$\alpha$），一次优化服务整个语料；INO 优化**单条文档的内容**，一次优化只服务一条更正。前者是全局的、离线的、需要重建索引；后者是局部的、增量的、不动索引结构。生产里两者可以叠加，但预算要分开算。

与 [A-RAG](du2026-a-rag.md) 与 [DCI](li2026-dci.md) 的对照在"谁来找"：那两篇让 agent 在查询时用工具主动找；INO 让文档在写入时就变得容易被找到。前者增加查询侧成本，后者增加写入侧成本。

## 可复现

论文没有给出代码或数据链接：语料是客户所有、反馈事件是生产数据，都不公开。可复现的部分是方法与评测口径：五个变体的定义（§4）、INO 的算法（Algorithm 1）、探针构造（4–6 条、与锚点不重叠）、上限三轮、反射器的输入与三条约束（§A）、三层指标（§3.4）、裁判的四维 rubric（§C）、动作性过滤的输入输出与校准方式（§D）、成本拆分（§E）。

已给出的关键数字：动作性过滤在 5,000 条切片上是 42.3%（聊天）/21.5%（工单），200 条人工标注上一致率 96.7%；100 条碎片来自 7 个客户；留出 410 条（110 历史 + 300 合成）；工单 160 条；负样本 1,400 条；收敛分布 56%/32%/12%；成本 0.31 美元、111.2 秒。

无法复现或未给出的部分：生产提示词的完整文本（附录只描述结构与输入字段）；检索栈的具体模型与阈值（只说"专有域数据微调过的稠密编码器"与"微调过的交叉编码重排器"）；客户语料的规模分布与每客户的碎片数；线上实验的样本量与用户数；裁判校准的具体提示词改动（"小幅提示校准"未展开）。
